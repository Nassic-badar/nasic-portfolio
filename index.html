Retrieval path 5 stages

PDF → text, page by page.

Extract text while keeping page boundaries and metadata intact. If the source is messy, the answer will be too — so this step gets more attention than it looks like it deserves.

PDF parsing · page metadata

Clean, split, overlap.

Break the document into passages that still mean something on their own: remove artifacts, keep enough surrounding context, and overlap the seams so answers don't fall between chunks.

text cleaning · overlap windows

Meaning, as geometry.

Turn each passage into a vector so meaning can be compared by distance instead of keywords. The embedding choice is a real design decision, not a default.

sentence embeddings · vectors

Find the nearest evidence.

Search the vector store for the closest passages and keep their page references attached. Retrieval quality is the difference between an answer and a guess.

Chroma · similarity search · top-k

Grounded, with receipts.

Generate from the retrieved context only, and return the source pages with every answer. A response you can't trace back isn't finished.

grounded generation · citations

02Method

Four steps, no shortcuts.

A method is just a promise you keep when the data gets ugly.

01

Frame the question

Before touching a dataset, I write down the decision it is supposed to support. If I can't name the decision, the chart is decoration.

02

Audit before analysis

Missing values, duplicates, impossible dates, silent type coercion. I profile the data first — most “insights” die in this step.

03

Explore, then model

Plots before p-values. A baseline before a neural net. If a simple model is enough, it ships.

04

Ship it legibly

A notebook is not a deliverable. I turn work into Streamlit tools, clean tables, and a short written explanation.

The best model is the one a non-technical stakeholder can question.
